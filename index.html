Your agents haunt you.
Haunt them back.

Six Claude Code and Codex sessions, and every one of them wants something from you: a permission, an answer, a nudge. bogyman is the thing under your desk that knows which agent has been waiting longest, what it's stuck on, and chases you down to deal with it. It never touches your terminals, tmux, or worktrees. It just stares.

A day haunted by Bogyman

The loop most people settle into once the bogyman moves in. Every step is one command; every command has --json.

  1. 01 · morning Start work however you like

    Three claude tabs, two Codex sessions, one task in the Desktop Code tab. The bogyman notices each one on its first hook.

    claude --bg "fix flaky tests" codex --session-name deps-audit
  2. 02 · glance Keep the count in your prompt

    Put bogyman status in starship, tmux, or your shell prompt. Cache only, under 20 ms.

    bogyman status ●2 ▶3 ✓1
  3. 03 · triage Answer the oldest wait first

    bogyman waiting lists blocked sessions by wait age. bogyman focus raises the tab, attaches to a background job, or fronts Desktop.

    bogyman waiting bogyman focus flaky
  4. 04 · unblock Reply without attaching

    Send a one-line answer and move on. Or let a supervising Claude session read bogyman ls --json and do the nudging.

    bogyman send deps "use pnpm" bogyman ls --json | jq '.data.sessions'

The CLI

Twelve commands. Human tables on a TTY, TSV when piped, JSON when asked. Exit codes you can branch on.

bogyman ls

Every live session, grouped blocked / working / done. --watch redraws each second.

bogyman waiting

Blocked only, oldest first. Exit 3 when empty, so it works in && chains.

bogyman status

One line for prompts and status bars. Cache only, <20 ms, templatable.

bogyman focus <id>

Raise the tab (iTerm2, Ghostty, WezTerm, kitty), attach a background job, or front Desktop.

bogyman send <id> "…"

Deliver a message. Wraps codex queue and Claude's reply path.

bogyman show <id>

Full record plus the last 20 events. --open jumps to the transcript.

bogyman install

Merges hooks into Claude and Codex settings. Idempotent, backed up, reversible.

bogyman doctor

Vendor versions, hooks registered, daemon health, last event per collector.

bogyman daemon

Optional poller for claude agents --json, Codex rollouts, and notifications.

bogyman gc

Prune records older than retention_days (default 7).

bogyman uninstall

Removes only bogyman's hook entries. Your other hooks stay untouched.

bogyman … --json

One envelope for every command: schema, command, ok, then data or error. Failures are JSON too.

$ bogyman ls --json | jq '.data.sessions[] | select(.state=="blocked") | {name, host, waiting_for, since}'
{ "name": "flaky-test-fix", "host": "terminal", "waiting_for": "permission_prompt", "since": "2026-10-26T21:03:11Z" }
{ "name": "Auth module refactor", "host": "desktop", "waiting_for": "question", "since": "2026-10-26T21:08:40Z" }
$ bogyman show zzz --json
{"schema":1,"command":"show","ok":false,"error":{"message":"no session matches 'zzz'","exit":1}}

Install in a minute

curl -fsSL https://raw.githubusercontent.com/soleo/bogyman-cli/main/install.sh | sh

One line, no package manager. Verifies the download against the release checksums and installs to ~/.local/bin. Or cargo install --git https://github.com/soleo/bogyman-cli bogyman-cli.

$ bogyman install                  # wires Claude Code + Codex hooks
$ bogyman doctor                   # both vendors report events
  • Merges into ~/.claude/settings.json and ~/.codex/hooks.json; existing hooks untouched; a .bogyman-bak is written first.
  • Nothing leaves your machine. Stores summaries and the first 200 characters of what a session is waiting on — never full prompts.
  • Claude Code ≥ 2.1.139 and Codex ≥ 0.130 for full coverage; degrades gracefully below.

How it works

  1. 1
    Hooks push events.

    bogyman hook runs on PermissionRequest, Notification, Stop, TaskCompleted, SessionEnd. Appends one row to SQLite, exits in <10 ms, never returns a decision.

  2. 2
    Pollers fill in detail.

    An optional daemon reads claude agents --json, Codex rollouts, and the Desktop session index for model, tokens, PR status, and titles.

  3. 3
    One record per session.

    Vendor, host, cwd, state, waiting_for, wait age, task progress. The CLI, the JSON, and any future UI read only this.

What it is not

Not a spawner. Not a kanban. Not a tmux layout. Not a cost dashboard. Those exist, a hundred times over. Bogyman is the thin layer that lurks alongside whatever you already use and answers one question well.
